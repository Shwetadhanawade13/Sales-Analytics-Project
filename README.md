# Sales Analytics Project

## Project Overview & Objective
The **Sales Analytics Project** aims to explore a real‑world online retail dataset to derive actionable insights that support data‑driven decision‑making. By integrating **Excel**, **SQL**, **Python (Pandas & NumPy)**, and **Power BI**, the project will demonstrate a full end‑to‑end analytics workflow—from raw data ingestion to interactive visualisation.

## Business Problem & Key Questions
- **Business Problem**: An online retailer wants to understand sales performance, customer behaviour, and product trends to optimise inventory, marketing, and profitability.
- **Key Questions**:
  1. What are the total sales and profit over time?
  2. Which products or categories generate the highest revenue?
  3. How does sales vary across regions and customer segments?
  4. What is the impact of cancellations and returns on net sales?

## Dataset
- **Name**: Online Retail
- **Source**: UCI Machine Learning Repository – [Online Retail Dataset](https://archive.ics.uci.edu/dataset/352/online+retail)
- **DOI**: https://doi.org/10.24432/C5BW33
- **License**: Creative Commons Attribution 4.0 International (CC BY 4.0)
- **Citation**:
  > Chen, D. (2015). *Online Retail* [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C5BW33

The official dataset documentation is maintained in [`data/README.md`](data/README.md) and is kept consistent with the information above.

## Tools & Technologies
- **Excel** – initial data inspection and quick pivot analyses.
- **SQL** – relational storage and complex aggregations (SQLite/PostgreSQL/ MySQL).
- **Python** – data cleaning, KPI calculation, and visualisation (Pandas, NumPy, Matplotlib).
- **Power BI** – interactive dashboard and report generation.

## Data‑Quality Considerations
- **Missing `CustomerID`** values are present for some transactions and must be handled during cleaning.
- **Cancellations** are indicated by `InvoiceNo` starting with **`C`**; these rows should be excluded or treated separately.
- **Returns** appear as negative `Quantity` values.
- **Duplicate records** may exist; deduplication is part of the data‑cleaning workflow (Issue 2).
